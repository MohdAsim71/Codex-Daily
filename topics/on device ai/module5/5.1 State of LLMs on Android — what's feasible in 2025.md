## 1. The On-Device LLM Landscape in 2025

```
Two years ago: "LLMs on phones? Impossible."
Today: Gemma 2B runs at 15 tokens/sec on a Pixel 8 Pro.

What changed?
  ✅ Quantization (INT4, INT8) — models 4-8× smaller
  ✅ NPUs in every flagship (98 TOPS on Snapdragon 8 Gen 3)
  ✅ Larger phone RAM (12–16 GB now common)
  ✅ Purpose-built small models: Phi-3, Gemma 2B, Qwen 1.5B
  ✅ Optimized runtimes: MediaPipe LLM API, MLC-LLM, llama.cpp
```

## 2. What "Feasible" Means on Android

Not all LLMs are equal for mobile. Here's the reality:

```
FEASIBLE on mid-range to flagship Android (2022+):
  ✅ Gemma 2B INT4      — 15–25 tok/s on Pixel 8 Pro
  ✅ Phi-3 Mini INT4    — 12–20 tok/s on Snapdragon 8 Gen 3
  ✅ TinyLlama 1.1B     — 25–40 tok/s on most flagships
  ✅ Qwen 1.5 1.8B INT4 — 20–30 tok/s

FEASIBLE only on flagship (2023+, 12GB+ RAM):
  ⚠️ Gemma 7B INT4      — 5–10 tok/s (Pixel 8 Pro, S24 Ultra)
  ⚠️ Phi-3 Small 7B     — 4–8 tok/s

NOT FEASIBLE on most Android phones:
  ❌ Llama 3 8B FP16    — 1–2 tok/s, often OOM
  ❌ Mistral 7B FP16    — too large
  ❌ GPT-4 class        — cloud only, no contest
```

## 4. Framework Comparison

```
Four main options for running LLMs on Android in 2025:

┌─────────────────────────────────────────────────────────────────────┐
│  Framework          Ease   Speed   Models    Backend                │
├─────────────────────────────────────────────────────────────────────┤
│  MediaPipe LLM API  ⭐⭐⭐⭐⭐  ⭐⭐⭐⭐   Gemma     GPU / CPU        │
│  MLC-LLM            ⭐⭐⭐    ⭐⭐⭐⭐⭐  Many      GPU (Vulkan)     │
│  llama.cpp (JNI)    ⭐⭐      ⭐⭐⭐    GGUF      CPU / GPU        │
│  ONNX Runtime       ⭐⭐⭐    ⭐⭐⭐    ONNX LLMs CPU / NNAPI      │
└─────────────────────────────────────────────────────────────────────┘
```

### MediaPipe LLM Inference API
- **Best for:** Getting started fast, Gemma models
- Made by Google, officially supported
- Kotlin-first API with coroutines support
- GPU acceleration via Metal/OpenGL ES
- Limited to Gemma family + a few others

### MLC-LLM (Machine Learning Compilation)
- **Best for:** Maximum performance, broad model support
- Compiles models to optimized Vulkan/CUDA shaders
- Supports Phi-3, Llama, Gemma, Mistral, Qwen
- 2–3× faster than CPU-based runtimes
- More setup complexity

### llama.cpp via JNI
- **Best for:** GGUF models, CPU inference
- Any GGUF model works — massive model library
- CPU-focused (GPU support via CLBlast)
- Requires JNI bridge (no native Kotlin API)
- Good for budget devices without strong GPU

### ONNX Runtime
- **Best for:** Smaller transformer models, NLP tasks
- Best for models under 3B parameters
- Native Android support via ONNX Runtime Mobile
- Less optimized for autoregressive generation

## 6. Quantization — Why It Matters for Mobile

Quantization is what makes LLMs fit on phones:

```
Gemma 2B — size at different precisions:
  FP32 (original)  → 8.0 GB  → ❌ Won't fit on most phones
  FP16             → 4.0 GB  → ⚠️ Needs 8 GB device
  INT8             → 2.0 GB  → ✅ Works on 4 GB devices
  INT4             → 1.3 GB  → ✅ Works on 3 GB devices ← USE THIS

Quality impact of quantization:
  FP32 → INT8: < 1% quality loss on most tasks
  INT8 → INT4: ~2–5% quality loss (noticeable on complex reasoning)
  INT4 is the sweet spot for mobile: small enough, good enough
```

## 7. Token Generation Speed — What Feels Good?

```
User experience by token/second:
  < 5 tok/s    → Frustratingly slow (feels broken)
  5–10 tok/s   → Usable but annoying
  10–20 tok/s  → Acceptable for most users
  20–30 tok/s  → Good — similar to reading speed
  > 30 tok/s   → Excellent — feels instant
```

**Gemma 2B on flagship = ~20 tok/s** — this is in the "good" range. Users can read the output as it streams.

## 8. Use Cases — What LLMs Are Good For On-Device

```
EXCELLENT (high accuracy, fast enough):
  ✅ Text summarization (notes, articles)
  ✅ Grammar correction / rewriting
  ✅ Simple Q&A on provided context
  ✅ Code explanation / generation (short snippets)
  ✅ Translation (though ML Kit is better for this)
  ✅ Chat / conversation assistant

ACCEPTABLE (works but may be slow or imperfect):
  ⚠️ Document Q&A with RAG
  ⚠️ Creative writing (limited context)
  ⚠️ Multi-step reasoning

NOT SUITABLE:
  ❌ Tasks requiring knowledge past training cutoff
  ❌ Long document analysis (>4K tokens context)
  ❌ Real-time responses (< 1s expected)
  ❌ Complex multi-hop reasoning chains
```

## 9. Privacy and Compliance Advantage

```
Cloud LLM                    On-Device LLM
─────────────                ─────────────
User text → API → Cloud      User text → stays on device
Subject to data retention    Zero data retention
Requires privacy policy      No AI processing policy needed
GDPR compliance complex      Inherently GDPR-friendly
Medical/legal: risky         Medical/legal: safe
Works offline: ❌            Works offline: ✅
```

On-device LLMs are the **only acceptable choice** for:
- Medical note summarization
- Legal document analysis
- Personal journal / diary apps
- Enterprise confidential documents
