## 1. Where Does LLM Memory Go?

Running Gemma 2B INT4 on Android consumes memory in three places:

```
Total memory usage: ~2.5–4 GB for Gemma 2B INT4

┌──────────────────────────────────────────────────────┐
│  Model Weights (static, loaded once)                 │
│  ~1.3 GB — the INT4 quantized parameters             │
├──────────────────────────────────────────────────────┤
│  KV Cache (dynamic, grows with conversation length)  │
│  ~200 MB–1 GB — key/value pairs for attention        │
│  Grows with each token in context window             │
├──────────────────────────────────────────────────────┤
│  Activation Memory (temporary, per inference step)   │
│  ~100–300 MB — intermediate layer activations        │
│  Freed after each token generation                   │
├──────────────────────────────────────────────────────┤
│  Android App + System Overhead                       │
│  ~500 MB–1 GB — OS, UI, database, other processes    │
└──────────────────────────────────────────────────────┘
```

**Key insight:** On a 6 GB RAM phone, after the OS takes ~2 GB, you have ~4 GB left. Gemma 2B needs ~2.5 GB — leaving only ~1.5 GB for everything else. Tight but workable.

## 2. KV Cache — The Hidden Memory Grower

The KV (Key-Value) cache is the #1 cause of OOM crashes in LLM apps:

```
Conversation turn 1:  "Hello!"
  KV Cache: small (~10 MB)

Conversation turn 10: many messages exchanged
  KV Cache: medium (~150 MB)

Conversation turn 50: very long conversation
  KV Cache: large (~600 MB)
  → Risk of OOM on low-RAM devices!
```

**Solutions:**

```kotlin
// Option 1: Reset chat after N turns (simplest)
private var turnCount = 0
private const val MAX_TURNS_BEFORE_RESET = 20

fun sendMessage(text: String) {
    turnCount++
    if (turnCount >= MAX_TURNS_BEFORE_RESET) {
        llmEngine.resetChat()   // clears KV cache
        turnCount = 0
        // Optionally: re-inject conversation summary
    }
    // ... proceed with inference
}

// Option 2: Monitor context length and warn user
fun checkContextLength(history: List<Pair<String,String>>): Boolean {
    val totalChars = history.sumOf { it.second.length }
    val estimatedTokens = totalChars / 4
    return estimatedTokens < 3500   // Gemma 2B has 4K context window
}
```

## 3. Check Available Memory Before Loading

Always check RAM before initializing an LLM — fail gracefully if not enough:

```kotlin
// MemoryChecker.kt
package com.yourname.chatapp

import android.app.ActivityManager
import android.content.Context
import android.os.Debug
import android.util.Log

object MemoryChecker {

    private const val TAG = "MemoryChecker"

    data class MemoryInfo(
        val totalRamMb: Long,
        val availableRamMb: Long,
        val usedByAppMb: Long,
        val isLowMemory: Boolean
    )

    fun getMemoryInfo(context: Context): MemoryInfo {
        val activityManager = context.getSystemService(Context.ACTIVITY_SERVICE)
                as ActivityManager

        val memInfo = ActivityManager.MemoryInfo()
        activityManager.getMemoryInfo(memInfo)

        val totalRam     = memInfo.totalMem / (1024 * 1024)
        val availableRam = memInfo.availMem / (1024 * 1024)

        // App's own heap usage
        val appHeapMb = (Debug.getNativeHeapAllocatedSize() / (1024 * 1024))

        return MemoryInfo(
            totalRamMb    = totalRam,
            availableRamMb = availableRam,
            usedByAppMb   = appHeapMb,
            isLowMemory   = memInfo.lowMemory
        )
    }

    /**
     * Check if device has enough RAM to load a model.
     * @param requiredMb  How much RAM the model needs (e.g. 2500 for Gemma 2B)
     * @return true if safe to load, false if risk of OOM
     */
    fun hasEnoughRam(context: Context, requiredMb: Long): Boolean {
        val info = getMemoryInfo(context)

        Log.d(TAG, "Available RAM: ${info.availableRamMb} MB")
        Log.d(TAG, "Required RAM : $requiredMb MB")
        Log.d(TAG, "Low memory   : ${info.isLowMemory}")

        // Add 500 MB safety buffer
        return info.availableRamMb >= (requiredMb + 500)
    }

    /**
     * Recommend the best model given available RAM.
     */
    fun recommendModel(context: Context): ModelRecommendation {
        val info = getMemoryInfo(context)
        val availMb = info.availableRamMb

        return when {
            availMb >= 5000 -> ModelRecommendation.GEMMA_7B
            availMb >= 3500 -> ModelRecommendation.PHI3_MINI
            availMb >= 2000 -> ModelRecommendation.GEMMA_2B
            availMb >= 1200 -> ModelRecommendation.TINYLLAMA
            else            -> ModelRecommendation.NOT_SUPPORTED
        }
    }

    enum class ModelRecommendation(
        val displayName: String,
        val requiredRamMb: Long
    ) {
        GEMMA_7B       ("Gemma 7B",      5000),
        PHI3_MINI      ("Phi-3 Mini",    3500),
        GEMMA_2B       ("Gemma 2B",      2000),
        TINYLLAMA      ("TinyLlama 1.1B",1200),
        NOT_SUPPORTED  ("Not Supported", 0)
    }
}
```

## 4. Lazy Loading — Don't Load Until Needed

LLMs should load lazily — only when the user actually needs them:

```kotlin
// LazyLlmManager.kt
package com.yourname.chatapp

import android.content.Context
import android.util.Log
import kotlinx.coroutines.*
import kotlinx.coroutines.flow.*

class LazyLlmManager(private val context: Context) {

    companion object {
        private const val TAG = "LazyLlmManager"
        // Unload model after this many minutes of inactivity
        private const val IDLE_TIMEOUT_MINUTES = 5L
    }

    private var engine: GemmaInferenceHelper? = null
    private var loadJob: Job? = null
    private var idleTimer: Job? = null
    private val scope = CoroutineScope(Dispatchers.IO + SupervisorJob())

    private val _loadState = MutableStateFlow<LoadState>(LoadState.Unloaded)
    val loadState: StateFlow<LoadState> = _loadState.asStateFlow()

    sealed class LoadState {
        object Unloaded : LoadState()
        object Loading  : LoadState()
        object Ready    : LoadState()
        data class Error(val message: String) : LoadState()
    }

    /**
     * Load model if not already loaded.
     * Safe to call multiple times — only loads once.
     */
    fun ensureLoaded() {
        if (_loadState.value == LoadState.Ready) {
            resetIdleTimer()
            return
        }
        if (_loadState.value == LoadState.Loading) return

        loadJob = scope.launch {
            _loadState.value = LoadState.Loading

            // Check RAM first
            if (!MemoryChecker.hasEnoughRam(context, 2500)) {
                _loadState.value = LoadState.Error(
                    "Not enough RAM (need ~2.5 GB). Close other apps and try again."
                )
                return@launch
            }

            try {
                Log.d(TAG, "Loading Gemma 2B...")
                val modelPath = "${context.filesDir}/gemma-2b-it-gpu-int4.bin"

                engine = GemmaInferenceHelper(context, modelPath)
                engine?.initialize()

                _loadState.value = LoadState.Ready
                Log.d(TAG, "Gemma 2B loaded")
                resetIdleTimer()

            } catch (e: OutOfMemoryError) {
                _loadState.value = LoadState.Error(
                    "Out of memory. Try closing other apps or using a smaller model."
                )
                engine = null

            } catch (e: Exception) {
                _loadState.value = LoadState.Error("Failed to load: ${e.message}")
                engine = null
            }
        }
    }

    /**
     * Unload model to free RAM.
     * Called automatically after idle timeout.
     */
    fun unload() {
        idleTimer?.cancel()
        engine?.close()
        engine = null
        _loadState.value = LoadState.Unloaded
        Log.d(TAG, "Model unloaded — RAM freed")
    }

    fun getEngine(): GemmaInferenceHelper? = engine

    /**
     * Reset the idle timer — if model is inactive for IDLE_TIMEOUT_MINUTES,
     * unload it automatically to free RAM for other apps.
     */
    private fun resetIdleTimer() {
        idleTimer?.cancel()
        idleTimer = scope.launch {
            delay(IDLE_TIMEOUT_MINUTES * 60 * 1000)
            Log.d(TAG, "Idle timeout — unloading model")
            unload()
        }
    }

    fun destroy() {
        unload()
        scope.cancel()
    }
}
```

## 5. Handle onTrimMemory — Android Memory Warnings

Android sends memory pressure signals. Always listen and respond:

```kotlin
// In your Application class or Activity
class ChatApplication : Application() {

    val llmManager = LazyLlmManager(this)

    override fun onTrimMemory(level: Int) {
        super.onTrimMemory(level)

        when (level) {
            // Moderate pressure — app is in background
            TRIM_MEMORY_BACKGROUND,
            TRIM_MEMORY_MODERATE -> {
                Log.d("Memory", "Moderate pressure — consider unloading model")
                // Optional: unload if not in active use
            }

            // Critical pressure — unload immediately
            TRIM_MEMORY_COMPLETE,
            TRIM_MEMORY_RUNNING_CRITICAL -> {
                Log.w("Memory", "CRITICAL memory pressure — unloading LLM")
                llmManager.unload()
            }
        }
    }
}
```

## 6. Model Lifecycle Rules

```
╔══════════════════════════════════════════════════════╗
║              LLM Lifecycle Best Practices            ║
╠══════════════════════════════════════════════════════╣
║  ✅ Load lazily (only when user opens chat screen)   ║
║  ✅ Close in ViewModel.onCleared()                   ║
║  ✅ Check available RAM before loading               ║
║  ✅ Reset KV cache every 20–30 conversation turns    ║
║  ✅ Unload when app goes to background (optional)    ║
║  ✅ Handle onTrimMemory with graceful unload         ║
║  ✅ Show loading state — don't block UI thread       ║
║                                                      ║
║  ❌ Never load model on main thread                  ║
║  ❌ Never hold two LLM engines simultaneously        ║
║  ❌ Never load on every Activity.onCreate()          ║
║  ❌ Never ignore OutOfMemoryError                    ║
╚══════════════════════════════════════════════════════╝
```

## 7. Memory Profiling with Android Studio

```
Steps to profile LLM memory usage:

1. Run app → Android Studio → View → Tool Windows → Profiler
2. Select your running process
3. Click "Memory" tab
4. Click "Record native allocations"
5. Load the LLM model in the app
6. Stop recording → see native heap breakdown

Key metrics to watch:
  Native Heap  → LLM model weights (should be ~1.3 GB for Gemma 2B INT4)
  Java Heap    → Android framework, your Kotlin objects
  Graphics     → GPU memory (hard to see directly)

ADB command to check memory quickly:
  adb shell dumpsys meminfo com.yourname.chatapp
```

## 8. OOM Recovery Pattern

```kotlin
// Graceful OOM recovery in ViewModel
fun sendMessage(text: String) {
    viewModelScope.launch {
        try {
            val engine = llmManager.getEngine()
                ?: throw IllegalStateException("Model not loaded")
            val response = engine.generateResponse(text)
            _uiState.value = _uiState.value.copy(response = response)

        } catch (e: OutOfMemoryError) {
            // Free as much memory as possible
            llmManager.unload()
            System.gc()

            _uiState.value = _uiState.value.copy(
                error = "Ran out of memory. Please close other apps and try again."
            )

        } catch (e: Exception) {
            _uiState.value = _uiState.value.copy(error = e.message)
        }
    }
}
```

## 10. Summary

- LLM memory = weights (~1.3 GB) + KV cache (grows) + activations (temporary)
- KV cache is the silent OOM killer — reset every 20–30 turns
- Always check available RAM before loading with `MemoryChecker.hasEnoughRam()`
- Use `LazyLlmManager` — load on demand, unload after idle timeout
- Listen to `onTrimMemory(TRIM_MEMORY_RUNNING_CRITICAL)` and unload immediately
- Catch `OutOfMemoryError` separately from `Exception` — different recovery path
- Never hold two LLM engines in memory simultaneously
