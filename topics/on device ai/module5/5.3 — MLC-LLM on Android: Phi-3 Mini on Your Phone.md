## 1. What is MLC-LLM?

```
MLC-LLM = Machine Learning Compilation for LLMs

Traditional approach:
  Model weights → Runtime interpreter → GPU/CPU
  (Interpreter adds overhead — slower)

MLC-LLM approach:
  Model weights → Compile to Vulkan/Metal shaders → GPU
  (Compiled code runs directly on GPU — faster)

Result: 2–3× faster than MediaPipe on the same hardware
        because shaders are pre-compiled for your specific GPU
```

**MLC-LLM supports (2025):**
- Phi-3 Mini, Phi-3.5 Mini
- Llama 3.2 1B, 3B
- Gemma 2B, 7B
- Mistral 7B
- Qwen 2.5 0.5B, 1.5B, 3B, 7B
- DeepSeek-R1 (distilled small versions)

## 2. Why MLC-LLM for Phi-3 Mini?

```
Phi-3 Mini 3.8B — why it's special:
  ✅ Microsoft's most capable small model
  ✅ Outperforms Llama 3 8B on many reasoning tasks
  ✅ Excellent at instruction following
  ✅ Strong code generation
  ✅ Only 3.8B params — fits on most flagship phones

MLC-LLM + Phi-3 Mini INT4 on Snapdragon 8 Gen 3:
  ≈ 18–25 tok/s   ← excellent for mobile
  ≈ 2.2 GB model size
  ≈ 4 GB RAM usage
```

## 4. Download Phi-3 Mini MLC Model

MLC models are pre-compiled for specific GPU architectures. Download the right one:

### Via Python (development)

```python
# download_phi3_mlc.py
# pip install huggingface_hub

from huggingface_hub import snapshot_download
import os

# Download Phi-3 Mini compiled for Android Vulkan
model_dir = snapshot_download(
    repo_id        = "mlc-ai/Phi-3-mini-4k-instruct-q4f16_1-MLC",
    local_dir      = "./phi3_mlc",
    ignore_patterns= ["*.md", "*.txt"]
)

print(f"Downloaded to: {model_dir}")
total_size = sum(
    os.path.getsize(os.path.join(r, f))
    for r, _, files in os.walk(model_dir)
    for f in files
) / 1e9
print(f"Total size: {total_size:.2f} GB")
```

### Via ADB push

```bash
# Push model to device
adb push phi3_mlc/ /data/local/tmp/phi3-mini-mlc/

# Or to app files directory
adb push phi3_mlc/ \
  /sdcard/Android/data/com.yourname.chatapp/files/phi3-mini-mlc/
```

## 5. MLCEngine.kt — Wrapper Around MLC-LLM

```kotlin
// MLCEngine.kt
package com.yourname.chatapp

import ai.mlc.mlc4j.MLCEngine
import ai.mlc.mlc4j.OpenAIProtocol.*
import android.content.Context
import android.util.Log
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.channels.Channel
import kotlinx.coroutines.flow.Flow
import kotlinx.coroutines.flow.flow
import kotlinx.coroutines.flow.flowOn
import kotlinx.coroutines.withContext

class MlcLlmEngine(
    private val context: Context,
    private val modelDir: String,        // path to phi3-mini-mlc/ directory
    private val modelLib: String = "phi-3-mini-4k-instruct-q4f16_1-android"
) {
    companion object {
        private const val TAG = "MlcLlmEngine"
    }

    private var engine: MLCEngine? = null
    private var isReady = false

    /**
     * Initialize MLC engine. Call once on app start.
     * Takes 3–8 seconds on first call (compiles shaders).
     * Subsequent calls are faster (cached shaders).
     */
    suspend fun initialize() = withContext(Dispatchers.IO) {
        try {
            Log.d(TAG, "Initializing MLC engine...")
            Log.d(TAG, "Model dir: $modelDir")

            engine = MLCEngine()
            engine?.reload(modelDir, modelLib)

            isReady = true
            Log.d(TAG, "MLC engine ready — Phi-3 Mini loaded")

        } catch (e: Exception) {
            Log.e(TAG, "MLC init failed: ${e.message}")
            throw e
        }
    }

    /**
     * Generate a response using OpenAI-compatible chat API.
     * MLC-LLM uses the same API format as OpenAI — easy migration.
     *
     * Streams tokens as they generate via Flow.
     */
    fun chat(
        messages: List<ChatMessage>,
        maxTokens: Int = 512,
        temperature: Float = 0.7f
    ): Flow<String> = flow {
        check(isReady) { "Call initialize() first" }

        val request = ChatCompletionRequest().apply {
            this.messages  = messages
            this.maxTokens = maxTokens
            this.temperature = temperature.toDouble()
            this.stream    = true    // enable streaming
        }

        var fullResponse = ""

        engine?.chat?.completions?.create(request)?.forEach { chunk ->
            val delta = chunk.choices.firstOrNull()?.delta?.content ?: ""
            if (delta.isNotEmpty()) {
                fullResponse += delta
                emit(delta)   // emit each token to the Flow
            }
        }

        Log.d(TAG, "Response complete: ${fullResponse.take(50)}...")

    }.flowOn(Dispatchers.IO)

    /**
     * Simple single-turn inference.
     * Returns full response as String (not streaming).
     */
    suspend fun generate(prompt: String, maxTokens: Int = 512): String =
        withContext(Dispatchers.IO) {

            check(isReady) { "Call initialize() first" }

            val messages = listOf(
                ChatMessage().apply {
                    role    = "user"
                    content = prompt
                }
            )

            val sb = StringBuilder()
            chat(messages, maxTokens).collect { token -> sb.append(token) }
            sb.toString()
        }

    /**
     * Build a messages list for multi-turn conversation.
     * Phi-3 uses OpenAI-style role/content format.
     */
    fun buildMessages(
        history: List<Pair<String, String>>,    // (role, content) pairs
        systemPrompt: String = "",
        newUserMessage: String
    ): List<ChatMessage> {
        val messages = mutableListOf<ChatMessage>()

        // System prompt (optional but recommended for Phi-3)
        if (systemPrompt.isNotBlank()) {
            messages.add(ChatMessage().apply {
                role    = "system"
                content = systemPrompt
            })
        }

        // Conversation history
        for ((role, content) in history) {
            messages.add(ChatMessage().apply {
                this.role    = role
                this.content = content
            })
        }

        // New user message
        messages.add(ChatMessage().apply {
            role    = "user"
            content = newUserMessage
        })

        return messages
    }

    /**
     * Reset conversation context.
     * Clears the model's KV cache — useful between independent sessions.
     */
    fun resetChat() {
        engine?.resetChat()
        Log.d(TAG, "Chat reset — KV cache cleared")
    }

    /**
     * Get model runtime statistics.
     */
    fun getRuntimeStats(): String {
        return engine?.runtimeStatsText ?: "Stats unavailable"
    }

    fun isInitialized() = isReady

    fun close() {
        engine?.unload()
        engine = null
        isReady = false
        Log.d(TAG, "MLC engine closed — GPU memory freed")
    }
}
```

## 6. Phi-3 Prompt Format

Phi-3 Mini uses a different prompt format than Gemma. MLC-LLM handles this automatically via the chat template in `mlc-chat-config.json`, but it's important to understand:

```
Phi-3 instruction format:
<|system|>
You are a helpful AI assistant.<|end|>
<|user|>
What is on-device AI?<|end|>
<|assistant|>
On-device AI refers to running machine learning models...

MLC-LLM applies this template automatically when you use
the ChatMessage API — you just pass role + content.
```

## 7. Usage in ViewModel

```kotlin
// ChatViewModel.kt (MLC-LLM version)
class ChatViewModel(application: Application) : AndroidViewModel(application) {

    private val engine = MlcLlmEngine(
        context  = application,
        modelDir = "${application.filesDir}/phi3-mini-mlc"
    )

    private val _modelState = MutableStateFlow<ModelState>(ModelState.NotLoaded)
    val modelState = _modelState.asStateFlow()

    private val _messages = MutableStateFlow<List<ChatMessage>>(emptyList())
    val messages = _messages.asStateFlow()

    private val _streamingResponse = MutableStateFlow("")
    val streamingResponse = _streamingResponse.asStateFlow()

    // Conversation history (role, content)
    private val history = mutableListOf<Pair<String, String>>()

    val systemPrompt = """You are a helpful, concise AI assistant.
        You run entirely on this device — no internet connection needed.
        Keep responses clear and brief."""

    fun loadModel() {
        viewModelScope.launch {
            _modelState.value = ModelState.Loading
            try {
                engine.initialize()
                _modelState.value = ModelState.Ready
            } catch (e: Exception) {
                _modelState.value = ModelState.Error(e.message ?: "Load failed")
            }
        }
    }

    fun sendMessage(userText: String) {
        if (!engine.isInitialized()) return

        // Add user message to history
        history.add("user" to userText)
        _streamingResponse.value = ""

        viewModelScope.launch {
            val messageList = engine.buildMessages(
                history       = history.dropLast(1),  // exclude the message we just added
                systemPrompt  = systemPrompt,
                newUserMessage = userText
            )

            val sb = StringBuilder()

            // Collect streaming tokens
            engine.chat(messageList, maxTokens = 512).collect { token ->
                sb.append(token)
                _streamingResponse.value = sb.toString()
            }

            // Add model response to history
            val fullResponse = sb.toString()
            history.add("assistant" to fullResponse)
            _streamingResponse.value = ""

            // Log performance stats
            Log.d("Chat", engine.getRuntimeStats())
        }
    }

    fun clearHistory() {
        history.clear()
        engine.resetChat()
        _messages.value = emptyList()
    }

    override fun onCleared() {
        super.onCleared()
        engine.close()
    }
}
```

## 8. MLC-LLM vs MediaPipe LLM — Performance Comparison

Test on Snapdragon 8 Gen 3, same prompt:

| Metric | MLC-LLM (Phi-3 Mini) | MediaPipe (Gemma 2B) |
|---|---|---|
| **Model size** | 2.2 GB | 1.3 GB |
| **RAM usage** | ~4 GB | ~2.5 GB |
| **Init time** | 5–8s (first) / 2s (cached) | 3–5s |
| **Tokens/sec** | 18–25 tok/s | 15–22 tok/s |
| **Quality** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ |
| **Setup effort** | Medium | Easy |
| **GPU backend** | Vulkan | OpenGL ES |
| **Model variety** | Many | Gemma-focused |

## 9. Runtime Stats — Monitor Performance

```kotlin
// Log performance after each generation
val stats = engine.getRuntimeStats()
// Output example:
// "prefill: 45.2 tok/s, decode: 22.8 tok/s, total: 3.2s"

// Parse and display
fun parseStats(stats: String): Map<String, String> {
    val result = mutableMapOf<String, String>()
    stats.split(",").forEach { part ->
        val kv = part.trim().split(":")
        if (kv.size == 2) result[kv[0].trim()] = kv[1].trim()
    }
    return result
}
```

## 10. When to Choose MLC-LLM vs MediaPipe

```
Choose MediaPipe LLM API when:
  ✅ Starting out — easiest setup
  ✅ Gemma 2B is sufficient for your use case
  ✅ You want official Google support
  ✅ Your users have 6 GB+ RAM phones

Choose MLC-LLM when:
  ✅ You need Phi-3 Mini (better reasoning)
  ✅ Maximum performance is required (25+ tok/s)
  ✅ You need model variety (Llama, Mistral, Qwen)
  ✅ Your users have 8 GB+ RAM phones
  ✅ You're comfortable with more complex setup
```

## 11. Summary

- MLC-LLM compiles models to GPU shaders — 2–3× faster than interpreted runtimes
- Phi-3 Mini 3.8B INT4 outperforms Gemma 2B on reasoning and coding tasks
- MLC uses OpenAI-compatible API — same format as OpenAI SDK (easy migration)
